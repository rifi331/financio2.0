# Plan: Align CardLink Credit Card Account Summary with cardlink.md spec (rev 3)

Repo: `bank-repositories/ms/ms-lib-esb-sdk` (branch `release/mvp1`). Strategy: **new spec-shaped request/response models + mapper into the existing `EsbDsspCreditCardAccountSummaryDTO`**, which is **enriched with new fields for everything card-related in the spec**. Spec-less fields stay null. Integration switches to **POST + JSON body**.

## 1. New request model (spec Input)

New DTOs in `com.hdh.ms.esb.rest.model.dto.clicks`, dropOff envelope style:

- `CreditCardAccountSummaryReqDto { CreditCardAccountSummaryRequest request }`
- `CreditCardAccountSummaryRequest { CreditCardAccountSummaryReqBody reqBody }`
- `CreditCardAccountSummaryReqBody`:
  - `rqUID` (String, M) — UUID generated per request
  - `cardNum` (String, M) — Primary Account Number
  - `orgNo` (String, M) — Customer Org
  - `acctInfo` → `AcctInfoReq { acctType }` — `CCA` / `KwikCard`
  - `identSerialNum` (String) — Customer ID (either-or with cardNum per spec)

## 2. New response model (spec Output)

`CreditCardAccountSummaryRespDto { response { respBody } }`:
- `respBody { rqUID, esbStatus { statusCode, severity, statusDesc }, acctInfo[] }`
- `AcctInfo`: `acctId`, `cardType`, `openDt`, `cycle`, `nplTagging`, `acctDelinquency`, `indicator`, `effDt`, `balanceAmount`, `acctTaxInfo { acctOrg }`, `bankAcctStatus { bankAcctStatusCode }`, `userCode[]`, `cardCustInfo { custStatusCode, custBScore, custEffDt, expDt, extAcctBal[] }`, `cardAcctInfo { blockCode, blockDate, altBlockCode, altBlockDate, cardSummInfo[] }`
- `CardSummInfo`: `cardOrg`, `cardType`, `cardNum`, `cardAcctName`, `cardAcctRel`, `cardStatus`, `blockCode`, `cardExpDt`, `transEffDt`, `cardActCode`, `newCardNum`, `newCardExpDt`, `actionCode`, `issueDt`, `cardLastExpDt`
- `ExtAcctBal { extBalType, curAmt { amt } }` — discriminated by `extBalType`

## 3. `EsbDsspCreditCardAccountSummaryDTO` changes

**Rename** `alertFlag` → `blockCode` (it was always the spec's Plastic Card Block Code; mapped from `cardSummInfo.blockCode`; mock updated accordingly). Existing fields kept, null when spec lacks them (`paymentDueDate`, `lastStatementDate`, `currentAmountDue`, `totalAmountDue`, `accountResidentType`, `isIslamic`). **New fields added**:

From `acctInfo[]` / `cardCustInfo`:
- `custStatusCode`, `custBScore`
- `custPermCreditLimit`, `custTempCreditLimit` (extBalType `CustPermCreditLimit` / `CustTempCreditLimit`)
- `custTempCreditLimitEffDt` (`custEffDt`), `custTempCreditLimitExpDt` (`expDt`)
- `acctOrg` (acctTaxInfo.acctOrg), `acctCardType` (acctInfo.cardType), `openDt`, `bankAcctStatusCode`, `cycle`, `userCodes` (List<String>)
- `acctBlockCode`, `acctBlockDate`, `altBlockCode`, `altBlockDate` (cardAcctInfo — account-level, distinct from plastic `blockCode`)
- `acctCreditLimit`, `acctCashBalance`, `acctRetailBalance`, `acctHighBalance`
- `cashliteEligibleAmt`, `cashliteAvailableAmt`, `availableCredit`, `tempLimit`, `overPmtAmt` (Acct*/Cust* extBalType variants)
- `nplTagging`, `acctDelinquency`
- `lastMonthPayments`, `lastCycleBals` (List<BigDecimal> — Last1st–6thMonthPayment / Last1st–6thCycleBal)
- `cppIndicator` (indicator), `effDt`, `retail1Balance` (balanceAmount)

From `cardSummInfo[]`:
- `cardOrg`, `plasticCardType`, `cardAcctName`, `cardAcctRel`, `cardStatus`, `cardExpDt` (already exists), `transEffDt`, `cardActCode`, `newCardNum`, `newCardExpDt`, `actionCode`, `issueDt`, `cardLastExpDt`

Existing-field sources in mapper: `acctId`/`accountNumber` ← `acctId`; `accountType` ← request acctType; `name`/`cardDesc`/`cardHolderName` ← `cardAcctName`; `creditCardAccountNo` ← `cardNum`; `cardAccountRelationType` ← `cardAcctRel`; `cardExpiryDate` ← `cardExpDt`; `orgId` ← `cardOrg` (fallback `acctOrg`); `currentBalance` ← `AcctCurrBalance`; `cardAvailableBalance` ← `AcctAvailableCredit`; `currencyCode` ← `"MYR"`.

## 4. Mapper + service + config

- MapStruct `CreditCardAccountSummaryRespToDtoMapper`: per `acctInfo` + first `cardSummInfo` → one DTO (existing SOAP-mapper flattening convention); balances resolved by `extBalType`, null when absent; `esbStatus.statusCode != 0` → existing error convention.
- `CreditCardAccountSummaryService`: both real paths build reqBody, use 7-arg `getInputDto` (dropOff pattern), map wrapper → `EsbPaginatedList<DTO>`. Mocks updated for the `alertFlag`→`blockCode` rename, otherwise unchanged.
- `ms-lib-esb-sdk.yml`: `esb-credit-card-account-summary` → `httpMethod: POST`, URI without `{ccNo}/{accType}` query params, JSON content type.
